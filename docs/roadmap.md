# Polaris: implementation roadmap

Dependency-ordered implementation briefs. The atlas foundation and briefs 6–7 (scout exploration and the first city/economy slice) are implemented; briefs 8–14 have follow-up issues #9–#15. The board is a **hex grid** with rules version 3 and generator version 4; the renderer draws hex fields from cubic voxels in 66×66-column chunks (`src/rendering/voxels.ts`), with territory borders, city name plates and voxel unit figures. Briefs below retain acceptance gates rather than implying every later gate is verified.

Sizes are rough focused-development estimates: **S** 1–2 days, **M** 3–5 days, **L** 6–10 days. Split an L brief before execution if acceptance cannot be reviewed together. Dependencies refer to brief numbers; on GitHub the same order is recorded as *blocked by* relationships between the issues, which every agent checks before starting work ([working order](../.github/copilot-instructions.md#working-order-issues-blocked-by-and-stacked-prs)). Work outside the numbered briefs gets its own issue in that chain: play by messenger #25, the voxel diorama #26, the hex voxel world #27 and the aligned agent guidance #28 follow #8 in this order, and #9 and #10 are blocked by #28.

**Outside the numbered briefs: play by messenger (implemented; issue #25).** A serverless two-player mode ([ADR-005](architecture.md#adr-005-serverless-play-by-messenger)) lets two people alternate turns by exchanging links, codes or files. It replays the deterministic command log, so every later rules change must stay deterministic and bump `RULES_VERSION`. Suggested follow-ups, not yet scheduled or filed as issues: delta packages once logs get long; verify the exchange on real iOS and Android browsers and decide whether the generator's trigonometry must become integer- or table-based; add a relay server or WebRTC only if hidden information, notifications or more than two players are required. (Drawing cities, founders and the opponent's units on the map is done with the hex voxel world.)

**Outside the numbered briefs: hex voxel world (implemented; issues #26 and #27).** Hex fields built from cubic voxels after the approved concept (`docs/concept-hex-voxel.jpg`), with territory borders, city name plates, voxel unit figures and on-demand rendering ([ADR-004](architecture.md#adr-004-map-and-rendering)). Issue #30 / stacked draft #31 adds shaded reference colours, four broad underwater terraces, irregular sandbanks, submerged and emerged coastal rocks, smaller trees, and sharp hex frames on both land and water; its integration remains blocked by #28. At the maintainer's request it also changes world generation: **generator v4** adds warped island silhouettes and deep, ocean-connected bays. Low connected highlands and broad, varied grey deposits replace the rejected per-hex grassy pillars. Older-generator local matches are retained without migration, and incompatible turns are explicitly rejected. Rules remain v3. Stone deposits, apple groves and fish occurrences have voxel scenery or original projected icons and inspection labels, but no harvesting or economic effect. This replaces the rejected flat water-cell shading, without waves or refraction. Still deferred: resource harvesting/worker extraction and further resource kinds, rivers and bridges, danger/attack markers once combat exists (brief 9), biome decorations such as palms, and fields and harbours around cities.
